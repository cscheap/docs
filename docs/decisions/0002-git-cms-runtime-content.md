# Git 正文与 CMS 动态读取

状态：Git/CMS 方向保留；直接内容 API 与双仓接入候选已由 [0003](0003-cms-editor-and-immutable-publication.md) 根据本地验证结果细化替代。以下保留当时的候选评估，不作为当前实施要求。

## 用户约束

正文长期由同一个 AI 读取各项目后统一编写，直到跨项目文档合并流程建立。Git 保存内容并记录各业务仓 SHA。用户接受前端改造，要求通过 CMS 等服务更新文档，避免每次正文变化都构建 frontend。

## 决定

- docs 保存全部用户正文；事实来源仍按项目记录。
- 保留现有 frontend 的 Fumadocs 页面及 URL，通过运行时内容 gateway 替代本地构建内容源。
- 优先验证 TinaCMS，其 Git 内容 API、MDX 模板和结构化正文输出与当前要求相符。
- 首选以 TinaCloud 双仓模式验证接入；不因此自动开通账号、付费或部署。需要自托管时另选兼容的后端宿主。
- 页面、导航、目录、搜索、语言和版本在同一发布流程内更新。内容变化与应用代码部署分别管理。

## 选择理由与边界

TinaCMS 原生以仓库文件为内容源，减少数据库 CMS 与 Git 之间的双向同步需求。Fumadocs 继续承担展示，TinaMarkdown 或等价适配器负责把结构化内容映射为 React 元素。

支持的 MDX 是预先定义的模板与属性，不包括随正文上传任意组件实现。修改已有组件的文字和属性无需构建 frontend；新增组件实现仍需部署。

Payload / Directus 等数据库 CMS 可以实现相同阅读体验，但本项目以 Git / MDX 为首要条件，需要额外解决导入方向与权威源。首期不采用它们作为默认方案。

## 尚待验证

1. 现有 React / Fumadocs / Cloudflare 环境中的结构化正文渲染。
2. CMS 索引与目标 Git commit 的对应关系、就绪检查和并发发布。
3. 前端替换只读静态缓存后，新页面、删除页面及搜索的动态更新。
4. 双仓模式的实际账号能力与接入配置；不得假定某个套餐免费包含全部能力。
