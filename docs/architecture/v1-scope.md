# 首版范围

本页记录用户最新确认的范围，优先于早期的分仓自动整合、前端内容包构建和独立文档站建议。

1. 建立 docs 仓库结构。
2. 确认对外文档目录。
3. 建立文档与多语言规范。
4. 根据当前实际能力初始化完整对外正文；用户所说的“日志”已澄清为文档正文。
5. 记录四个项目的 GitHub SHA 等信息，关联正文与代码版本。
6. docs 的 master 更新后经 Git 编辑、校验后编译并发布内容包，frontend 动态读取，不再触发前端整站构建。

## 已确认的维护方式

在项目文档合并到 docs 的机制建立前，只由当前一个 AI 读取 spider、refinery、api、frontend 并完成所有正文和复核。用户接受前端改造，2026-10-10 确认用 Git 编辑与 R2 发布简化内容服务。

正文以 Git 为权威来源，英文为主，中文与俄文为翻译。AI 直接维护 MDX，不依赖在线编辑器。

## 并行变化

各独立业务变化用独立文档 PR；依赖同一跨项目行为的页面需要联合复核。基线按项目拆分，减少无关文件冲突。

必须区分文件冲突、语义不一致与旧构建覆盖新发布三类问题。一个 AI 负责文档可以减少作者协调成本，但不能消除业务并行变化；文档必须基于固定 SHA，而不是阅读期间持续变化的工作区。

基线捕获不等于正文已核对，也不证明对应代码已在生产部署。各基线的 documentationReview 为 pending 时，不得作为完整正文已完成的证据。

## 本期排除

- 多项目 AI 委派与跨仓自动汇总 PR。
- 自动抓最新业务分支并未经核对升级文档。
- 独立对外文档子域名及同域名多应用转发。
- 文档更新触发 frontend 构建或修改 frontend 内容锁。
- 任意 JavaScript / 新 React 组件免前端部署。
- 将内部运维资料和未开放功能直接发布为客户文档。
