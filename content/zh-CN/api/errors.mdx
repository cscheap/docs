## 按状态与错误码处理

| 状态 | 含义与处理 |
| --- | --- |
| 400 | 费率写入引用了你无法使用的对象时返回 `validation_error`（`error.details.missing` 逐项列出 `kind`、`id` 与 `reason`）；批量查询的 `cursor` 被改动时返回 `invalid_cursor`。修正请求。 |
| 401 | 缺失或无效认证，检查当前密钥。 |
| 402 | `credit_insufficient`，补充点数或检查订阅。 |
| 403 | `forbidden`，该凭证无权执行操作。`subscription_required`：保存自己的费率记录需要有效订阅，读取不受影响。 |
| 404 | `resource_not_found`，检查路径、标识与覆盖。 |
| 405 | `method_not_allowed`，检查 HTTP 方法与 `Allow` 头。 |
| 409 | `conflict`，记录在你读取后已被修改（例如 `expected_sequence` 已过期），或链仍在使用中。重新读取后再重试。 |
| 422 | `validation_error`，修正字段约束再重试。`unsupported_currency`：请使用官方货币代码。 |
| 429 | `rate_limited`，按 `Retry-After` 等待。 |
| 500 | `internal_error`，保留请求 ID，持续失败时报告。 |
| 503 | `dependency_unavailable`，稍后退避重试。 |

校验详情可能包含 `error.details.errors`，条目带有 `loc`、`msg`、`type`。响应不一定回显输入，不要依赖英文错误文字做程序判断。

失败的价格请求不扣点数，但丢失成功响应是另一种情况，见[重试](/docs/guides/polling-and-retries)。
