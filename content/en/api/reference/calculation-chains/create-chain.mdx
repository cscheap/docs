## Operation

`POST /calculation-chains`

## Behavior

Creates a calculation chain and returns it as revision 1 with its steps expanded.

- Each step references an existing operator by ID and `kind`. You may reference your own operators, official ones and those other users share. Every unavailable reference is listed in a 400 under `details.missing`, with the `reason` `not_visible`.
- Saving checks the chain exactly as `POST /calculation-chains/validate` does without `start_currency`: any `error` issue (for example consecutive steps whose currencies do not line up) returns 422 with the issues under `details.issues`, and nothing is saved.
- `apply_to` binds the new chain to marketplace slots in the same request, each with the slot `sequence` you read as `expected_sequence`. All or nothing: a stale sequence (409) or a refused step (400) leaves no chain behind and every slot unchanged. `applied` lists the bound slots.
- The chain is yours and not official; set `is_searchable` to share it.
