## Operation

`GET /prices/export`

## Behavior

Downloads the quotes of every priced item of one game as one file, for bulk synchronization. `side` defaults to `ask`; `side=mid` exports only the `CSCP` valuation of every valued item, a much smaller file.

- The body is the export document itself (`app_id`, `side`, `generated_at`, `items`), gzip-compressed (`Content-Encoding: gzip`) — not the usual envelope. The request id and the billing fields are response headers instead: `X-Request-ID`, `X-Billable`, and on a billed response `X-Credit-Cost` and `X-Credit-Remaining`.
- `items` lists every item with at least one quote on the requested side, ordered by market hash name; each item's quotes follow the same rules as `GET /prices`.
- The file is a snapshot rebuilt on the server every few minutes; `generated_at` (also the `X-Export-Generated-At` header) says when. Requests in between receive the same file.
- Send the `ETag` you received back as `If-None-Match`: while the snapshot is unchanged the answer is `304 Not Modified` with no body, and a `304` is never billed.
- `Range` requests are not supported; the whole file is always sent. There is no pagination or market filter.
- `503 dependency_unavailable` means the first snapshot has not been built yet; retry after a minute.

> [!warning]
> Every `200` is billed, even when the file has not changed. Poll with `If-None-Match` and you only pay when there is something new.
