## Операция

`PUT /website-calculation-chain-bindings/{website_code}/{purpose}`

## Поведение

Привязывает ревизию цепочки расчёта (`calculation_chain_revision`, по умолчанию текущую ревизию цепочки) к одной площадке и назначению, заменяя ранее привязанное вами, и возвращает итоговый слот.

- `expected_sequence` — последний прочитанный `sequence` слота (0 для слота, в который ещё не писали): если слот с тех пор изменился — 409, и ничего не меняется.
- Другая цепочка должна быть вашей собственной, официальной или открытой другим пользователем (иначе 400) и не быть помеченной устаревшей (409).
- Повторная привязка более ранней ревизии требует, чтобы всё, что она использует, ещё существовало: иначе 409 с `details.missing` (`reason` `deleted`).
- Повторная привязка уже привязанного выполняется успешно, даже если к этой цепочке с тех пор закрыли доступ.
- 400, если код площадки неизвестен.
- Привяжите встроенную цепочку `0`, чтобы зафиксировать, что назначение бесплатно; если комиссия неизвестна, вместо этого удалите привязку.

> [!note]
> Этот запрос задаёт вашу личную привязку, которую видите только вы.
